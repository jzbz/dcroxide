# Consensus- and security-critical dependency ledger

[SECURITY.md](../SECURITY.md) states the gap this file starts to close:
*"Nobody has read the dependencies."* `cargo-deny` runs on every push and
gates the RustSec advisory database, a licence allow-list, yanked crates, duplicate major versions and
unknown sources — an automated check against problems someone else already
found, not a review.

This ledger does not claim a review has happened. It records **a decision
per dependency**, so the trust status of the load-bearing subset is explicit
rather than implied, and so a version bump of one of them is a decision
rather than a silent `Cargo.lock` change. The precedent is
[ADR-0002](adr/0002-vendor-blake256-from-dcr-rs.md): BLAKE-256 was vendored
into the tree precisely because it is consensus-critical.

Cuprate reached the same problem from the other side — pinning crypto and
storage crates to exact git revisions, maintaining frozen forks, and
eventually co-maintaining its curve library. Most of those rungs do not fit
a single-maintainer pre-alpha, and the sizes below are why: vendoring
`ring` would mean adopting 151k lines of C and assembly.

## Decision vocabulary

- **vendored** — the code is in this tree, pinned and attributed.
- **owned** — written in this tree, as opposed to vendored: the project
  wrote it and maintains it, and its tests are the only check it has.
- **reviewed@V** — a human has read the parts this node depends on, at
  version V. Bumping past V requires a fresh look.
- **accepted** — used as-is on stated grounds, without a read. This is an
  honest status, not a placeholder: most entries below are here.
- **declined** — considered and not adopted.

The scope is the ~12 crates whose behaviour is observable in consensus, key
handling, or the network surface, out of roughly 210 packages in the lock file,
plus `windows-sys`, the one crate the workspace's own `unsafe` code calls.
Everything else is `accepted` by default and not listed.

## Inline assembly the pure-Rust rule allows

[ADR-0012](adr/0012-pure-rust.md) allows no C or C++ in anything that
ships or that `cargo test` builds, and no cryptographic routine written in
assembly. It allows tiny inline-assembly barriers and system calls, each
named here; CPU intrinsics (`core::arch`) are Rust and need no entry. The
table is every crate in `Cargo.lock` whose `asm!` is compiled for a target
the project builds for (CI's test matrix, x86_64 and aarch64 Linux, macOS
and Windows, and the no_std check's `x86_64-unknown-none`). It was found on
2026-10-26 by searching each locked crate's `.rs` files for `asm!`,
`global_asm!` and `naked_asm!` and reading the `cfg` of each site. A bump
that changes one of these sites, or a crate that brings a new one, needs
its entry here before it lands; nothing checks this mechanically.

## Test vectors taken from elsewhere

`crates/dcroxide-tlscrypto/tests/data/wycheproof/` holds ten of
Wycheproof's vector files (AES-GCM, ChaCha20-Poly1305, HMAC-SHA256,
HMAC-SHA384, HKDF-SHA256, HKDF-SHA384, X25519, and ECDH over P-256, P-384
and P-521) from
[C2SP/wycheproof](https://github.com/C2SP/wycheproof) at `d17cc89f`
(2026-10-23), fetched on 2026-10-26 and committed gzipped, with the
repository's Apache-2.0 `LICENSE` beside them. `SOURCE` there records the
commit and each file's size, SHA-256 and git blob hash as fetched. They are
test data and build into nothing that ships. Refreshing them is a fetch at
a new commit, recorded the same way, and the harness pins each file's case
counts, so a file that changes under it fails until the counts are
re-pinned on purpose.

## What is deliberately not here

`cargo-vet` is not wired up. It is the natural mechanical backing for this
ledger — audits committed to the repo, so bumping a critical crate requires
a recorded decision — and it should be adopted when there is more than one
maintainer to exchange audits with, or when the project imports another
organisation's audit set. For a single maintainer it would currently
restate this table in a format nobody else reads. Recorded as a decision
rather than an oversight.

Vendoring beyond ADR-0002 is declined for every crate above, on size:
`ring` is ~151k lines, `secp256k1-sys` ~67k, `curve25519-dalek` ~35k,
`redb` ~54k. Each figure is `wc -l` over the published crate's `.c`,
`.h` and `.S`/`.s` files for the first two, and over its `.rs` files for
the other two. ADR-0002's precedent applies to code small enough to own,
which BLAKE-256 was and none of these are.

## Maintaining this

Add a row when a dependency becomes consensus-observable or reaches key
material. Change a row's decision when someone actually reads the crate —
`reviewed@V` is a claim about a person having done that, and should not be
written otherwise.
